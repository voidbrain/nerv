# NERV Agency style guide

NERV Agency is a local proactive personal agent. Its symbol (owner choice, 2026-11-04) is an original inverted triangle with seven almond eyes in rows of 4, 2 and 1: `web/public/mark.svg`, used for the browser icon and the native menu. The web sidebar shows `web/public/brand.svg`, an original half leaf beside the same triangle. Both are project-local geometry in one colour, dark NERV red `--mark` (#d4002a, 3.15:1 on `--bg`, above the 3:1 graphics minimum; deeper reds fall below it), with eyes and veins cut out. An SVG loaded as an image cannot read CSS variables, so the files carry the literal value and test/brand.test.ts keeps it equal to the token. They are evocations, not copies: never ship the Evangelion NERV leaf or SEELE mask artwork, which are third-party trademarks. No raster, stock or generated concept art is shipped as the mark.

Use the tokens in `web/src/styles.css` as the palette source of truth: dark navy surfaces, pale text, muted labels and seafoam actions. The marks are one colour. Use system sans-serif for controls and Georgia italic for the introductory line. No remote fonts. Generous spacing, visible focus, persistent labels and explicit error messages. Main copy is calm and concrete. Avoid claims of connected devices or delivered phone notifications unless observed.

The workspace contains stable navigation, reminders, local inbox and diagnostics. GenUI foundations use validated Web Component descriptions; it does not replace navigation or inject executable code. Distinguish planned, configured, connected, observed and failed states.

English is the default UI language; Italian is selectable (the language switcher stays). Keep messages in web/src/i18n.ts with matching keys. User reminder content is never translated automatically. Browser date inputs and formatted dates use browser local time, explicitly labelled; server configuration defaults to Europe/Rome for future scheduling semantics. Changing the UI language does not reinterpret stored UTC deadlines. CLI command names and raw doctor fields remain technical English.

The status card uses the existing theme tokens through a Shadow DOM. Shadow DOM encapsulates styles; it is not a security boundary. The current surface is deterministic, not LLM-generated. Preserve text escaping and bounded descriptions in every renderer.

The native menu uses a monochrome template drawing of the seven-eye triangle, with English default and Italian selection. The scrollable menu displays at most five pending reminders and Mac-local dates. Quit companion leaves the daemon running. Native pairing uses a SecureField; never show or copy the administrative bearer token into the app. Local forget and server revocation are distinct. Native/system error details may retain the OS language.

Notification enablement says “from now”; denied/failed permissions remain visible. Stop NERV Agency uses a destructive confirmation; Quit companion is a separate action. Service loaded, daemon connected and login enabled/approval-required must be shown as distinct states. Never present OS notification submission as proof the user saw a banner.

The NERV dashboard (`web/public/dashboard/`) has its own look, chosen in three parts (F-047): **Theme** *Eva* (lore labels, square panels, filled headers, Share Tech Mono, optional CRT) or *Simple* (plain labels and layout); **Mode** dark or light; **Colour** orange, blue, green, violet or ochre. The colour tokens come from one function, `palette()` in `dashboard.js`, applied as the same `var(--…)` tokens the stylesheet uses; a new colour or token goes there, and test/dashboard.test.ts checks that every text and focus colour reaches WCAG AA (4.5:1) on every background in all 20 combinations. Eva · Dark · Orange is the original EVA Full and also the stylesheet's `:root`, so the first paint before the script matches it. The four EVA cages keep their own colours (`--eva00` to `--eva03`), deeper in light mode. Choices are remembered per browser; an older single theme name maps to its nearest (EVA Full and EVA Basic to Eva · Dark · Orange, Dark to Simple · Dark · Blue, Light to Simple · Light · Blue, Terminal to Simple · Dark · Green). In live mode, a panel without real data says *planned · not connected yet*; it never shows the simulation's invented numbers next to real ones. An empty panel says why it is empty and what to do next ("No reminders. Ask Misato … below, or on Telegram"), never just "none". A sortie card carries one plain sentence of why (where it stands and the reason), written by the service from the ledger. Keyboard shortcuts are single keys outside text fields (`/` search; `a` approve and `r` reject); a key that decides anything needs a second press, and the first press says in visible text, also announced, what the second will do.

In the Eva theme the dashboard carries lore scripts beside the English: Japanese for the MAGI (each seat's kanji large, `.mk`, in `--kanji`) and Hebrew for the Sephirot (`lang="he"`, no letter spacing). Both use `.jp-only`, so the Simple theme shows only the English. A Sephirot node shows its number and its Hebrew and Latin name top left (the English meaning on hover), the crew avatars top right, its title and one line of state; the eleven nodes are numbered 1 to 11 in the order a sortie passes them.

Beside the header clock, a small outlined button shows an incrementing build version (`v1.N`, where N counts first-parent commits, advancing once per merge on main; package version is the fallback without full git history); its hover text and accessible name give the full commit, and a click copies it, saying *copied* or *copy failed* for a moment. It shows the code the service started with, not the checkout's current state, and is hidden without a live base.

A live dashboard preserves its last data through one failed poll. Repeated failures say *REFRESH DELAYED* when authenticated status still answers, *STATUS UNAVAILABLE* when its HTTP reply is an error, or *SERVICE UNREACHABLE* when the probe gets no reply; both retry automatically. A successful refresh clears the warning. Errors name the API endpoint; only an authentication refusal asks for sign-in again.

The Angular build loads its full stylesheet directly: critical-CSS extraction is disabled because its inline activation script is blocked by the service CSP. Keep external scripts required by that policy. The registered status card follows the page h1 with an h2; subsequent content sections are also h2. `npm run test:browser` checks applied styles, bilingual controls, browser-local dates, responsive widths and axe accessibility in Chrome.

At narrow widths the Angular navigation wraps rather than widening the page; the main grid item can shrink within a 320 px viewport.

Pilot model controls belong in the Marduk Institute/Pilots panel: the Generic pilot model is the fallback adviser, and each specialist card has its own labelled selector and Apply button. Choices list installed local Ollama models; missing saved models are labelled unavailable. Preserve drafts during polling. The Models panel contains Misato and Casper plus cloud-route settings; pilot cloud routing remains planned.

Muted badges use `--text` on their tinted background so the small labels retain AA contrast.

The map legend has two visually distinct headings, “■ Bases” and “- Kaji line”, with online/standby/offline and plug/result/sync entries; Midori is the round Telegram channel node. There is no extra legend title or map cloud caption. Base labels use one size and their status colour; a larger square identifies main and a larger circle identifies this base (combined when they coincide). Midori’s marker/name use the offline colour when no fresh API response exists; there is no “Unknown” caption under it. Contour health pulses are smaller. The map and legend share a height. Plug means dispatched work, result means returned work output, and sync means an observed Kaji heartbeat. Live budget cards show cost tracking as unavailable until accounting is connected.

Pilot model rows keep the visible “Model” label, selector and Apply button inline. The accessible name retains the pilot identity. Apply is disabled for the saved selection, unavailable choices and in-flight changes; choosing a different installed model enables it, and saving or reverting disables it again.

A forwarded sortie detail names the answering base and shows its full destination sortie reference when received. It describes actions on this base only; waiting and failed relays never claim a tool-free answer. An enrolled Kaji protocol address is not a dashboard link. Local empty sorties distinguish planning, failure, stopping and completed answers.

Telegram routing in the bases panel separates route checks from send outcomes. A stale/offline report reads unknown with its last reported mode and checked time; absent telemetry reads state not reported. “Accepted” means a send was accepted through main or the local bot, with its timestamp; phone receipt remains unknown. No private channel identifiers or message content belong in telemetry.

Models and Battery share one panel with keyboard-accessible tabs; hiding a tab preserves its model draft through polling. Battery remains explicitly planned until accounting exists. The budget shortcut reveals the Battery tab. Pilot model selectors remain in their own cards.

Midori’s signal means a recent Telegram API response, never merely configuration/listener startup or phone receipt. Incoming owner messages and accepted outbound sends pulse in their actual direction, without replaying the initial snapshot; empty polls never pulse. Each base keeps polling its own bot and accepting owner messages while outgoing inbox deliveries route through main. The map draws the active outbound path (main only when routed; local edges for fallback). Per-base API status and last received/send timestamps remain separate, with a coloured Midori summary beside the base count.
