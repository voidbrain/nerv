2. Flows (ingress → done)
Happy path (conceptual)
textUser / channel / schedule
    → Entry Plug (normalize intent, schema)
    → Gendo L3: assign Blue | Orange | Red
         ├─ Blue: skip full MAGI (or thin check) → Ritsuko sync ≥ threshold
         │         → issue A.T. Field token → EVA worker → Dogma commit
         ├─ Orange: MAGI (± experts) → majority approve → Ritsuko → token → EVA → Dogma
         └─ Red: MAGI and/or force HITL → Misato approve/reject
                   → only then token → EVA → Dogma
    Failures / low sync / API down → Dummy Plug fallback or HITL
    Rollback → Spear of Longinus (revoke token + ledger compensate)
When are consultants / experts evaluated?
Docs + backlog (not fully productized):


Case,Step,Experts?
Blue (read-only / routine),"After Gendo, often before full MAGI",Usually no — skip council; experts not required
Orange (bounded transform),Gendo → MAGI active; L3 may select committee,Optional / dynamic: fixed specialists or JIT suggest-only can be pulled into the ballot or as side counsel
Red (mutation / privileged),MAGI + HITL,Experts may advise; they must not auto-grant Red authority (F-024)
Low sync / policy split,Ritsuko fails threshold or 2/3 fails,"HITL; experts can brief Misato, not bypass her"
Skill/expert promotion,"After execution, offline eval",Shadow → bounded → fuller role (Kaji pipeline; experts same discipline as skills)


So: experts are not on every job. They enter when Gendo’s dynamic committee selection (or an Orange/Red policy) asks for them—typically alongside or under MAGI, never as a silent Red auto-approve.
Your example: Tokyo-3 with 3 MAGIs (Claude, local, German base)

Resident MAGI 01 at Tokyo-3 can be heterogeneous: e.g. Melchior = cloud Claude, Balthasar = local Gemma, Casper = model served from NERV-02 (Germany).
That is configuration of the three seats, not three separate NERV orgs.
Changing seats = operator/config + trust rules (who may vote, from which node, with which keys).
Forge additional MAGIs?
Core trio: tightly controlled; not casually spawned (docs: keep core MAGI membership tight).
Optional / on-demand pool: yes in the design — “optional MAGI / expert pool”, remote seats, JIT experts.
Ask USA base to share one? Fits M3 multi-node + M2/M5 model routing: a remote node exposes a model endpoint; Tokyo-3 enrols it as a temporary or fixed voter/specialist under progressive trust—not free federation of Red power.

Resident vs JIT
Resident: always-on seats (classic Melchior/Balthasar/Casper).
JIT experts: suggest-only or temporary seat after evaluation (F-024); rollback removes seat/capability.


Dashboard today only simulates council votes; it does not provision remote MAGI seats.

6. Direct answers to your questions

Consultants/experts in evaluating? Yes in the design, mainly Orange/Red and when Gendo’s dynamic committee pulls them; not routine Blue. Same progressive-trust ladder as skills (shadow → bounded → possible temporary seat); never silent Red authority.
Tokyo-3 with Claude + local + German MAGI? Valid resident trio composition across nodes; changeable by config/trust, not by a toy button today.
Forge more MAGIs / JIT / ask USA base? Optional pool + JIT + remote seats are in the architecture/backlog spirit; core 3 stay controlled; remote share = enrol model capability under mesh auth + trust—not free vote minting.
Neo Tokyo-3? Primary Geofront / coordinator base.
EVA? Worker/sandbox unit.
Pilot? Capability/skill identity plugged into that unit.
Stats that matter: per MAGI vote+resources+node; system sync; per-EVA sync/status; mesh link health; Dogma lag; trust stage; token scope/TTL; HITL queue; pattern outcomes.

Bottom line: Gendo should auto-route; Spear should be real revoke/compensate; MAGI/experts should run on Orange/Red with explicit seats. dashboard-agnostic.html visualizes the story and simulates the path; it is not yet the armed control plane.
