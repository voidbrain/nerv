# Node discovery, inspection and confirmed bootstrap

F-005 adds selected-target, operator-confirmed bootstrap and CLI discovery from selected inventory files, literal SSH aliases, an optional Tailscale status export/client and root-verified registry bundles. Discovery never probes a range automatically, enrolls a host, starts a worker or grants a tool. Registry addresses are candidate locators, not evidence that SSH is available. Reported Tailscale online state remains source metadata, not a fresh NERV health check.

## Read-only inspection

`nodes inspect` runs a fixed Node probe locally or over an explicitly selected SSH destination. SSH uses batch authentication, strict existing known-host checks, no agent/X11/port forwarding, no known-host updates and no multiplexed session reuse. It never accepts a host key automatically. The client still uses the owner's SSH configuration and authentication setup; these are not a sandbox. Literal alias discovery does not evaluate Include or Match/Proxy commands. See the authoritative [OpenSSH client](https://man.openbsd.org/ssh.1) and [configuration](https://man.openbsd.org/ssh_config.5) references.

The child runner forwards a narrow OS/client environment, not NERV/provider/Telegram credentials. Reports contain OS/architecture, Node/Git/npm versions, hostname/user home, current UID where available and selected public default-base metadata. Credentials, SQLite state, model requests and service controls are excluded. `runtime: not-checked` is deliberate: configuration and a successful SSH command do not prove a running or enrolled worker. Only the default `.nerv/config.json` is inspected; custom NERV_HOME/legacy locations and actual service ownership require separate inspection.

Input inventories are regular files bounded to 256 KiB; candidate sets contain at most 64 entries. Reports are bounded to 16 KiB; SSH output including discarded stderr is bounded to 32 KiB and the read-only command has a 15-second deadline. Errors discard raw stderr. No secret or private key appears in command arguments or reports. `--out` creates a new mode-0600 file and refuses overwrites. Keep actual host reports private and outside git.

## Preview contract

A preview binds the validated inspection/digest, SSH locator, observed hostname/platform/runtime, full 40-character source commit, separate absolute checkout/data paths under the inspected user home, proposed base identity, permissions and optional service action. Reports expire after 24 hours. The digest detects changed data; it is neither an enrollment signature nor authority to execute. Unknown/raw report fields do not enter the manifest.

The source repository is fixed to NERV's repository. Planning reads the selected commit's bootstrap declaration through bounded `git show`; older commits without protocol 1/fresh model-free initialization are refused. A format-valid SHA alone is not compatibility evidence. The preview lists clone/fetch/checkout and explicit revision verification, locked `npm ci --engine-strict`, build, initialization with `--fresh --no-model-setup` and public-identity commands. The bootstrap initialization never queries Ollama or selects Misato/Casper routes, including when an endpoint is configured in the inherited environment. The server's Node 24 floor alone does not establish build compatibility: the pinned source/dependency engines must pass. Package lifecycle scripts are code and require review; this is not an untrusted-tool sandbox. No model download or provider account is configured by the preview.

Known missing dependencies and root execution appear as blockers. Existing default configuration also blocks fresh installation unless the owner explicitly selects `--additional-profile`: this mode permits only new, separate directories and can never install/start a second service. Fresh initialization refuses existing configuration or credentials instead of changing them. Service ownership/session support is not inspected automatically and blocks a service preview until reviewed. A fresh-install preview never authorizes replacing or migrating an existing NERV/Nodo definition. `nodes plan` returns review data and never executes. `nodes apply --plan FILE --confirm DIGEST` requires the exact reviewed digest. It reconstructs the manifest rather than trusting saved commands, verifies target identity/runtime and new-directory ownership, then runs fixed typed steps locally or over strict SSH. Directories are claimed atomically; source SHA and bootstrap capability are rechecked on the target. No enrollment, model discovery, service start or arbitrary shell/MCP tool is exposed. `--service` previews remain blocked until separate ownership/session review; service installation and existing-profile update/uninstall use the reviewed manual procedures, not this fresh-files executor.

## Durable execution and recovery

The target stores a private owner-marked `.nerv-bootstrap/journal.sqlite`. An SQLite writer transaction atomically rechecks cached receipts and directory preconditions, claims the per-user bootstrap resource and persists acceptance before business effects. Each step checks its nonce/owner and persists started/completed progress. The terminal receipt and resource deletion commit together. Progress is not installation success; completed receipts describe this bootstrap operation, not later service/enrollment state.

Timeout, disconnect, child crash and step failure retain uncertainty and their resource. The transport has a 15-minute deadline; individual commands have four-minute bounds. A target may continue after a transport timeout. Replaying the same digest reads the stored receipt and never silently restarts uncertain/released work. `nodes status --plan FILE` is read-only, works after preview expiry and exposes a recorded handler PID when held; that PID alone does not establish liveness or stopped descendants.

`nodes release --plan FILE --confirm DIGEST --confirmed-stopped --reason EVIDENCE` requires actual operator confirmation that the handler and descendants stopped, and refuses a still-live handler. A transaction compares the exact digest/PID/nonce snapshot before releasing, so stale concurrent reconciliation cannot delete a newer resource. It records the reason without deleting checkout/data or assuming effects undone. Unknown journal ownership is refused, never migrated or erased automatically. An old released digest remains non-executable.

Target-side checks protect the intended filesystem paths and journal; these are same-user boundaries, not protection against a compromised host or malicious approved dependency. The helper transmits only fixed reviewed code plus validated data, never model-generated code. No new model-callable execution tool or local `/rpc` mutation is registered.

Pairing keeps the target's private base key on the target. The owner independently compares its public fingerprint, signs enrollment on the coordinator, and transfers only signed registry/public-root material. There is no root/admin/provider credential distribution or trust on discovery. Verify doctor and an explicitly approved harmless capability after installation; no startup or discovery message proves execution.

Recovery instructions retain checkout/data/keys/logs and require reconciling observed steps after failure or timeout. They do not claim automatic rollback, deletion or undo. Before reusing physical resources, inspect actual state. Downgrade/database restore remains F-062; restoring an old receipt journal is not a safe default.

## Remaining F-005 work

[Lifecycle review contracts](node-lifecycle.md) now validate supplied ownership evidence and recovery decisions for macOS/Linux. They do not collect service evidence or extend this executor; `--service` remains blocked.

Automated service/update/uninstall ownership flows, additional discovery adapters and full real-device pairing/worker/lifecycle acceptance remain open. The supported executor is fresh filesystem/configuration bootstrap only; manual lifecycle commands remain independently reviewed. The local Mac is the first acceptance target; an existing default NERV configuration prevents treating it as a fresh machine. No remote host was chosen or modified. F-014/B-045 supply the enrolled worker transport; this feature reuses it rather than opening an execution tunnel in local `/rpc`.
