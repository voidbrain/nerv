# Hyuga proactive watch

Assessment date: 2026-11-09. Baseline: main `cd8142d`, after F-027-T01 provenance acceptance. Scope: F-026-T01 admission and gate limits; T02 runtime/configuration/notification integration remains planned. This is an architecture assessment and decision, not a scoped audit, model campaign or production activation.

The existing reminder ticker and brief/consolidation schedules prove that A can persist idempotent local work while B is unavailable. They do not provide a general proactive trigger queue. An in-memory timer alone would lose duplicate suppression and cancellation state after a restart. A second execution authority would conflict with the existing grant gate. Retain the scheduler's SQLite ownership and the existing Ledger proposal/authorization path.

T01 introduces `Watch` in A's Store with validated, owner-authored definitions and a bounded durable queue. It starts no timer and exposes no chat configuration tool. Heartbeats use UTC interval buckets; daily schedules use the owner's IANA timezone and local date. Missed heartbeat buckets/days are not backfilled. A repeated DST hour shares one daily identity; a skipped daily time becomes due after the jump. Event subscriptions cover completed/failed non-Hyuga sorties, start at the current event head when created/re-enabled/changed, and retain the event's source/taint. They do not inject event text into a prompt or recursively consume their own results.

Each trigger/slot creates at most one sortie in the same transaction as its queue identity. Definition edits do not recreate an existing slot. At most twenty pending/running runs are retained; event cursors stop advancing when admission is full. A durable claim is not automatically replayed after process loss: interruption revokes remaining grants, preserves the ledger's happened-effects evidence and requires a new explicit job/slot. Pending or running work is revoked when its definition is removed/changed or its configured pilot stage changes. Cancellation cannot become successful completion.

Limits freeze the admitted pilot's current stage (generic defaults to Prototype), per-trigger reserved-action count and planning-step count. Trigger data cannot declare its own stage; a missing/retired named pilot prevents new admissions and revokes its prior work before reporting the configuration error. The Ledger caps caller stage and uses the stricter existing Scrolls, taint and EVA rules. Non-Production proactive work is read-only and selects EVA-00 unless stricter quarantine applies. Outside code needing missing confinement is rejected. Hard read-only, isolation and action-budget denials do not become owner cards after the reject limit. Approved/waiting actions reserve budget; declining a card does not replenish it. These are action/step counts, not monetary or token limits; measured model usage remains separate.

Alternatives rejected: prompt-only read-only instructions cannot constrain execution; coordinator-only queues lose restart identity; treating every retry as a fresh job hides uncertainty; application URL filtering is not an OS sandbox. No actual EVA confinement is claimed (F-049). Reconsider scheduling/backfill or capacity only with an owner requirement and measured load/recovery evidence, preserving identity, quiet-hour and grant requirements.

T02 must connect explicit validated owner configuration, local planner consumption, approval/cancellation/restart outcomes and deferred quiet-hour notifications. It must preserve reminders and deliveries already due, re-read changed permissions before execution, enforce the planning-step budget, and establish the actual A/C/B/channel/native joins before F-026 closes. Merely adding T01 tables does not enable proactive models, claim phone notification receipt, satisfy quiet-hour delivery or close the parent.

Evidence: validation, schedule/DST/quiet-schema, SQLite restart/deduplication/event cursor, cancellation and gate-budget regressions in `test/watch.test.ts`; F-027/MCP/ledger regressions run across the changed gate. Initial independent review found disabled-subscription replay and cancellation/completion mismatch; both fixed with regressions, including real reopening and pilot demotion. Follow-up review also found pilot retirement/removal could leave old authority; fixed by revoking it before reporting the configuration error. Final independent recheck passed all12 Watch tests, no blockers. Broad local suite483 passed/two skips;43 focused gate/Watch/provenance/MCP regressions passed. Full CI remains pending.

Consistency: README capability claims, AGENTS/area notes, BACKLOG-RULES and style guide inspected; no UI or active runtime claim changed. Architecture, owning tasks, decision map and generated work views describe the inactive first slice and remaining T02 acceptance. No calendar/model invocation or cross-repository release requirement is added.
