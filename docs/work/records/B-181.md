| **Issue** | Found 2026-11-27 in the design review of [F-146-T03](F-146.md) (PR #870): `loadSkillVersion` (`src/skills.ts`) reads `manifest.json` and `SKILL.md` from the private store without checking them against a digest recorded when the version was staged or promoted. **Next action / closure evidence:** 2026-11-27: B-181-T01 implemented. `stageSkillPackage` records `digest` (sha-256 over every stored file of the version: relative path, length and bytes, in path order) in the registry; `activateSkillVersion` refuses to promote a version whose stored files no longer match it, and `chooseActiveSkill` refuses a matching active one (`skill.refused`, "its stored files changed since it was staged: stage, evaluate and promote a new version."), so its instructions never reach the planner. A version staged before the digest existed is refused the same way until a new version is staged. The refusal names the registry's id and version, not the edited manifest's. Limit: the digest sits in the registry in the same private store, so it binds the promoted version against edits of the package files, not against someone who also rewrites the registry.
