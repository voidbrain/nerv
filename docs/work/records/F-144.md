| **Issue** | Owner decision 2026-11-26 in chat: "ollama a+b, c as option in dashboard". The first reply after an idle period is slow because Ollama unloads a model about 5 minutes after its last use and the next request reloads it (gemma4:26b is about 16 GB, gemma4:12b about 8 GB). Three parts: **A** NERV asks Ollama to keep its role models loaded longer after the last use (default 30 minutes, configurable); **B** NERV warms the model at known moments (service start, after an update, about 1 minute before a scheduled brief or reminder that needs it); **C** "keep loaded always" (keep_alive -1) as an owner option in the dashboard Settings, off by default, with a memory warning (a pinned model conflicts with VMs and with ComfyUI image runs, which unload models; the image runner's `--unload-ollama` interplay is [F-144-T06](#f-144)). Plus time to first token, cold against warm, shown in `nerv doctor` and the dashboard so the gain is visible. How NERV calls Ollama today: `src/engine-provider.ts` sends OpenAI-compatible `/v1/chat/completions` (streamed) and no `keep_alive`; Ollama's `/v1` endpoint may ignore `keep_alive`, so [F-144-T01](#f-144) decides between native `/api/chat` and a prompt-less `/api/generate` with `keep_alive` after each reply. |
| **Reproduce** | Leave NERV idle for more than 5 minutes (`ollama ps` shows the model gone), then send a chat message: the first reply waits for the model to load. |
| **Check** | A request carries the configured `keep_alive` on local Ollama role calls only (T01, T02); the models are loaded after a service start, an update and shortly before a scheduled brief, never blocking a reminder when Ollama is down (T03); "keep loaded always" is off by default, validated, and does not fight an image run (T04, T06); cold and warm time to first token shown in doctor and the dashboard (T05, T07); the owner sees the faster first reply (T08). |
