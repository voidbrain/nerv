<summary>Next action, estimates and evidence</summary>

**Plan (planning only, 2026-11-26):**
- **Where.** No sudo: `~/.local/bin/nerv` on macOS and Linux (the XDG user bin; `/usr/local/bin` needs root on both and is not written). Windows: `%USERPROFILE%\.nerv\bin\nerv.cmd` beside the existing hidden launcher, and the user PATH is not edited silently: `service install` and `doctor` print the one line that adds the folder. When `~/.local/bin` is not on PATH the install says so and prints the line to add; it never edits `~/.zshrc`, `~/.profile` or any shell file.
- **What.** A small generated launcher, written next to the service definition from the same inputs as `renderService` (`stableNode`, `NODE_FLAGS`, `root/src/cli.ts`, `home`): POSIX `#!/bin/sh` with `NERV_HOME` exported then `exec <node> <flags> <root>/src/cli.ts "$@"`; Windows `.cmd` with the same. One pure function (`renderLauncher(platform, home, root, node)` in `src/service.ts`, sharing the path and flag code with `renderService`) so the unit and the launcher cannot drift. A file `nerv` that is not ours (no generated-by marker) is never overwritten: the install reports it instead.
- **When.** `service install` and `service move` write it; the lifecycle update (`src/engine-lifecycle.ts`, the plan that already rewrites `servicePath`) rewrites it when the rendered content differs and removes it with `service uninstall`.
- **Doctor.** `doctor` reports `nerv` on PATH: missing, resolves to a launcher for another root or Node, or to a symlink into a development checkout (the old `npm link`); each with the one command that fixes it (`nerv service install` or the full path to the launcher).
- **Docs.** INSTALL.md: the installed base uses the launcher; `npm link` is for development only and says so.

**Tasks:** B-169-T01 failing tests (launcher content and target for darwin, linux and win32; not overwriting a foreign file; the update rewrites a stale launcher), B-169-T02 `renderLauncher` and the install, move, update and uninstall wiring, B-169-T03 the `doctor` check, B-169-T04 INSTALL.md and the area note, B-169-T05 owner check with copy-paste steps (below).
