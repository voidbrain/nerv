| **Issue** | Owner approved 2026-11-25, from the F-120-T01 [Gauntlet coverage review](../../reviews/gauntlet-coverage/2026-11-25.md) (section 3, finding). [F-084](../../archive/backlog-2026.md#f-084)'s closure check promised that "the instruction load is measured in tokens and a model route that cannot hold it is refused; long work is split into steps, each in a fresh session with a persisted handoff". The [coding job contract](../../decisions/coding-job-contract.md) (section 4) specifies both, but no code under `src/` measures the instruction load at admission or persists step handoffs for coding jobs (`src/coding-job.ts`), and no test or F-084 evidence covers them. F-084 stays closed; this record owns the gap. |
| **Reproduce** | `grep -rn "instructionTokens" src/` finds nothing; `test/coding-job.test.ts` has no admission or handoff test. |
| **Check** | Before each step a coding job measures `AGENTS.md`, `CLAUDE.md`, the triggered procedure files and the task prompt with the route's token counter (or characters ÷ 4) and refuses, with the reason, a route whose context cannot hold the load plus 16,384 tokens (32,768 minimum); a job longer than one step runs each step in a fresh session from a persisted handoff that survives a restart; tests across the join (coding job → runner → handoff store) and an agent run on a scratch repository recorded in `docs/acceptance/`. |
