<summary>Next action, estimates and evidence</summary>

**Root cause (evidence so far):** the service accepts and records a valid receipt (tests and the bogus-receipt probe), and the worker's click handler sends it; since no tap on two installs ever arrived, the request is lost on the phone. WebKit has open reports that match: `notificationclick` not firing for Home Screen apps ([WebKit 268797](https://bugs.webkit.org/show_bug.cgi?id=268797)), the click handled in a separate process before the page loads ([252544](https://bugs.webkit.org/show_bug.cgi?id=252544)), `openWindow` landing on the app's root ([263687](https://bugs.webkit.org/show_bug.cgi?id=263687)). Which one applies shows at the retest in the log (`push: opened via worker|page`); the fix covers all three.

**Scope:** steps B-170-T01 failing tests, T02 page report, T03 device-bound subscriptions, T04 Done, T05 procedure and notes, T06 owner retest. Assumption (cheap to undo, also in the PR): a notification the owner removed from Notification Centre before opening the app counts as seen, like a tap; one still shown never counts, nor one the phone did not list by its tag right after showing it (design review: an empty or tagless `getNotifications` must never confirm). A paired device's id covers one push app: where two installed apps on one origin share `localStorage` (desktop or Android, not iOS Home Screen apps), enabling push in one replaces the other's subscription; Telegram still falls back. The workspace app (`workspace-sw.js`) keeps the worker-only report for now: the owner's push app is the dashboard.

**Implemented 2026-11-26 (B-170-T01 to T05):** tests committed first and failing on main (`test/push-opened.test.ts`, 7 cases); expectations unchanged since; two harness fixes (the done sign-in call sent the default token; the fakes gained `getNotifications` and `match` for the review fix). `test/pwa.test.mjs` now counts 5 live.js API calls (the new report). The worker tags each push with its receipt, keeps it in Cache Storage and opens `/dashboard/?opened=<receipt>`; `live.js` reports it and kept receipts whose notification is gone (before sign-in, `via: "page"`); `/api/push/opened` takes `via` and logs `push: opened via <route>: recorded|unknown receipt`. `push_subscriptions.device_id` (additive): a paired device's new subscription replaces its old one, revoking it removes them. `reminder_done` (additive table) and `POST /api/reminders/<id>/done`; `dashboard/history` returns `recent` (delivered in 24 h, not done), shown in Coming up with **Done**. Retest steps: see the human-action line.

**Estimates:** Medium (5.5 h agent), estimated 2026-11-26: T01 1 h, T02 1.5 h, T03 1 h, T04 1.5 h, T05 0.5 h; T06 owner 0.5 h. Not a measurement.
