<summary>Next action, estimates and evidence</summary>

**Root cause (evidence so far):** the service accepts and records a valid receipt (tests and the bogus-receipt probe), and the worker's click handler sends it; since no tap on two installs ever arrived, the request is lost on the phone. WebKit has open reports that match: `notificationclick` not firing for Home Screen apps ([WebKit 268797](https://bugs.webkit.org/show_bug.cgi?id=268797)), the click handled in a separate process before the page loads ([252544](https://bugs.webkit.org/show_bug.cgi?id=252544)), `openWindow` landing on the app's root ([263687](https://bugs.webkit.org/show_bug.cgi?id=263687)). Which of these applies is not proven from the Mac; T02's log line (`push: opened … via worker|page`) shows it at the retest. The fix does not depend on which.

**Scope:** steps B-170-T01 failing tests, T02 page report, T03 device-bound subscriptions, T04 Done, T05 procedure and notes, T06 owner retest. Assumption (cheap to undo, also in the PR): a notification the owner removed from Notification Centre before opening the app counts as seen, like a tap; one still shown never counts. The workspace app (`workspace-sw.js`) keeps the worker-only report for now: the owner's push app is the dashboard.

**Implemented 2026-11-26 (B-170-T01 to T05):** tests committed first and failing on main (`test/push-opened.test.ts`, 7 cases); one test call then changed without changing its expectation (the done sign-in case passed `undefined`, which took the default admin token; it now sends no bearer). The worker tags each push with its receipt, keeps it in Cache Storage and opens `/dashboard/?opened=<receipt>`; `live.js` reports it and kept receipts whose notification is gone (before sign-in, `via: "page"`); `/api/push/opened` takes `via` and logs `push: opened via <route>: recorded|unknown receipt`. `push_subscriptions.device_id` (additive): a paired device's new subscription replaces its old one, revoking it removes them. `reminder_done` (additive table) and `POST /api/reminders/<id>/done`; `dashboard/history` returns `recent` (delivered in 24 h, not done), shown in Coming up with **Done**. Procedure: [retest](../../acceptance/f004-t06-phone-push-procedure.md#tap-recorded-retest-b-170-t06), with the copy-paste removal of the deleted app's subscription.

**Estimates:** Medium (5.5 h agent), estimated 2026-11-26: T01 1 h, T02 1.5 h, T03 1 h, T04 1.5 h, T05 0.5 h; T06 owner 0.5 h. Not a measurement.
