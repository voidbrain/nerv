### B-177

**The nervous process grows to ~590 MB on a Raspberry Pi: two timezone checks per scheduler tick pile up native ICU memory**

|:---:|---|---|---|
| 🔴 | 🔶 P2 | Open | 🟡 Medium |

💻 **→ Human action required: No**<br />Next: B-177-T03, the read-only RSS check on NERV-03 once it runs a build with B-177-T02; B-177-T04 (other hot-path formatters) can start now.

| | |
|---|---|
| **Issue** | Owner asked 2026-11-26 where NERV's memory goes (a smaller base, e.g. a Pi Zero 2 W with 512 MB, cannot run NERV today). On NERV-03 (Raspberry Pi CM4, 3.7 GB, Debian 11) `nervous-process.ts` was 579–593 MB RSS after 2.5 h, 2.8× the Mac's 207 MB with a smaller database. Cause found: `readConfig` (`src/config.ts`) checked the timezone by building a new `Intl.DateTimeFormat` on every call, and the nervous scheduler calls it twice per 250 ms tick (`Store.tick`: reminder defaults and FPV), about 29,000 formatters an hour. Each holds about 36 KB of ICU memory outside the V8 heap, so V8 sees no pressure and collects late; on Linux glibc keeps the freed memory in the process (`[heap]` 471 MB of the 593 MB on NERV-03). macOS returns more of it, so the Mac looks smaller. |
| **Reproduce** | Linux arm64 container (`node:24-bookworm-slim`), a temp NERV home with `config.json` `{"timeZone":"Europe/Rome"}`, `Store.tick()` and `Store.expire()` driven by a 1 ms interval, 4 ticks each: main reaches RSS 636 MB at 8,000 ticks and 1,737 MB at 40,000 (malloc `[heap]` 631 MB). Test: `test/config-timezone.test.ts`, "B-177: reading config.json again does not build a new Intl.DateTimeFormat for the same timezone" (committed as `todo`, failed with 100 formatters for 100 reads). |
| **Check** | The B-177 test passes; on NERV-03, after 2 h or more running the fix, `nervous-process.ts` RSS stays near its start-up size (target under 250 MB) and does not rise across samples a few minutes apart; the planned steps below give a measured minimum host size in `docs/INSTALL.md`. |

<summary>Next action, estimates and evidence</summary>

**Evidence, NERV-03 (read-only, 2026-11-26 23:15–23:25):** `uname -m` aarch64, `getconf LONG_BIT` 64, dpkg arm64, Node v24.22.3 (Mac: v26.12.0), no V8 pointer compression on either, V8 heap limit 2,090 MB, no `NODE_OPTIONS`. Checkout `89d67918`. `nervous-process.ts` (pid 1192, up 2.5 h): VmRSS 592,632 kB = VmHWM, RssAnon 529 MB, RssFile 63 MB, no swap; `smaps` `[heap]` (malloc) 471 MB, other anonymous 58 MB, node binary 61 MB; flat at 592,652 kB across samples one minute apart after 23:20 (579 MB at 23:15). `cli.ts serve` 211 MB, `brain-process.ts` 113 MB (VmHWM 131 MB), no `tools-process.ts`.

**Measured locally (Mac, Node 24.19 and 26.12, throwaway temp homes):** bare Node 70 MB RSS; importing `store.ts` brings it to 131 MB (113 of 189 `src` files); the CDP, desktop, slicer and Kaji imports add nothing on top: `store.ts` already loads them. One tick built 2 `Intl.DateTimeFormat`, both at `config.ts:292`. 2,000 `new Intl.DateTimeFormat(..., { timeZone })` add 72 MB RSS on both Node majors; one reused formatter adds 1 MB over 30,000 formats. With the fix, the Linux container run above stays at 201–219 MB RSS over 40,000 ticks (malloc `[heap]` 75–92 MB). With a GC every 200 ticks macOS plateaus near 20 MB either way: late collection plus allocator retention, not a reference leak.

**Ruled out:** 32-bit Node (arm64 on both), a different Node major as the cause (24 and 26 grow alike), database size, V8 heap growth (`heapUsed` stays 18–30 MB).

**Separate:** on NERV-01 three leftover `nervous-process.ts` test runtimes (`f107-t02` worktree, `kaji-reach-a-*` homes, up 4 days) hold 440–833 MB each; not stopped.

**Plan:**
- B-177-T01: failing test (done in this PR).
- B-177-T02: `readConfig` checks each timezone once per process (done in this PR).
- B-177-T03: on NERV-03, after it runs a build with B-177-T02 for 2 h or more, sample the three processes' VmRSS and `[heap]` twice 5 minutes apart (read-only `ssh`, as above); record the numbers here.
- B-177-T04: the other formatters built per call (`src/reminder-time.ts`, `src/chronicle.ts`, `src/brief.ts`, `src/update-scheduler.ts`, `src/misato.ts`, `src/why.ts`): a failing test that counts constructions per call, then one small cache of formatters by locale and options.
- B-177-T05: per-process start-up footprint on NERV-03 and the Mac after B-177-T03 (`--heap-prof` and `process.memoryUsage()` at READY in a temp home): which subsystems `store.ts` loads that the nervous process never uses, and whether lazy imports save more than 10 MB a process.
- B-177-T06: small-host settings, measured on NERV-03 with a throwaway instance: a capped V8 heap per child and glibc `MALLOC_ARENA_MAX=2` in the service definition for hosts under 2 GB; adopt only what a measurement shows.
- B-177-T07: a measured minimum host size in `docs/INSTALL.md`. Today's floor: four Node processes at 70 MB bare plus about 60 MB of modules each is over 500 MB before any work, so a 512 MB Pi Zero 2 W is not supported; running the children in fewer processes would be a feature for the owner to decide.
