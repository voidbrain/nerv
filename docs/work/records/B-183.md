**Next action / closure evidence:** 2026-11-27: B-183-T01 implemented. `StorePush.status()` reports `devices` (subscriptions bound to a paired device; revoking a device already removes its own, B-170) and `unpaired` (the rest, which still receive pushes). Health's Phone push line and the base card read "N device(s) · M unpaired subscription(s)", and say "no device subscribed" only when there are none of either. Chosen over hiding them: an unpaired subscription still gets every push (a browser subscribed with a dashboard session, or an earlier install), so the owner should see it. Cleanup, automatic: when a paired device saves a subscription, unpaired ones whose user agent names the same platform (the first word in its parentheses: iPhone, iPad, Macintosh, …) are removed, so an earlier install's leftover goes, and a Mac browser stays when the phone subscribes. Limits: a second device of the same platform subscribed without pairing (an admin token in the app) loses its subscription and must enable notifications again; the owner's phone must subscribe once more to be bound (B-183-T02).
