# NERV Agency area notes

## Local core

Node 24 runs erasable TypeScript directly. `src/store.ts` owns SQLite state; `src/server.ts` owns authenticated loopback HTTP; `src/cli.ts` owns process lifecycle; `src/config.ts` owns private per-user configuration and `src/service.ts` renders/manages user services. Validate untrusted input before writes. Do not expose arbitrary SQL, shell execution or tools through chat. Keep delivery creation and reminder completion in one transaction. `npm test` covers restart, duplicates, cancellation and HTTP authentication. These are NERV Agency's current conventions, not a published reusable Node harness profile.

## Action gate and ledger

`src/policy.ts` is the pure per-action ballot (F-017) and `src/ledger.ts` the sortie ledger, grants, approvals and events (F-024, F-023) in the same SQLite file, owned by A during serve. Names follow docs/NERV/NERV-ARCHITECTURE.md; code keeps plain names. Every agent action goes through `Ledger.propose` and every executor call through `Ledger.authorize`; never execute a tool from a ballot result alone. Unregistered tools are irreversible (Pattern Blue). The Scrolls come from `scrolls.json` in the data home (`readScrolls` in `src/config.ts`, validated by `validatePolicy`); the CLI and the scheduler process both load it, and an invalid or others-writable file stops startup rather than falling back to the defaults. Casper (`src/casper.ts`) runs in the brain process on the local route only and sees the owner's request and the exact action, never planner reasoning; a failed or unreadable reply is no verdict, never an approval. The coordinator (`Runtime.act`) asks Casper only when `Ledger.preview` says the action is not Green. Executors (`src/executors.ts`) live in the scheduler process next to the grant: `Store.runAction` and `Store.decide` call `authorize` and then the executor, so grant IDs never leave that process, and a repeated decision never runs a tool twice. A new tool declares its effect class there; an unregistered tool has no executor and stays Blue. Misato (`src/misato.ts`) plans in the brain process, one JSON step per model call, and never executes: `Runtime.chat` gates each proposed action, feeds the outcome back and stops at a reply or `MAX_STEPS`. Facts the model handles badly are computed in code, not asked of it: due times arrive already converted (`dueLocal`), a step waiting for the owner says it is not done, and an identical proposal already waiting never reaches the gate twice. The reply language follows the request. Lilith (`src/memory.ts`, schema 4) holds facts with provenance and an append-only history; recall is FTS5 with user words quoted, so no input becomes an FTS operator; `memory.remember` is an `owner` tool (always Pattern Blue, whatever the Scrolls say), so Misato never stores a fact on its own; the coordinator offers matching facts with each request, and on the cloud route only shareable ones. Instrumentality (`src/instrumentality.ts`, `Runtime.consolidate`) turns the exchanges since the last episode into a stored summary and candidate facts, proposed as `memory.remember` cards in an `instrumentality` sortie (Casper not asked; closed when every card is decided); facts already active or waiting are skipped (`factKey`), the ledger is never changed. A tool Misato was not offered goes back to it as invalid, never to the owner as a card. `settings.schedule` is the only settings tool: it changes the brief time and the Instrumentality schedule in config.json (Green, reversible); `serve` re-reads both every minute; anything security-relevant (models, Telegram, Scrolls, base) stays out of chat's reach. The loop's request, steps and waits are `misato.*` events, so `Runtime.sweep` resumes a sortie from the ledger alone once every approval it waited for is decided (any source: Telegram, API, CLI, expiry, also across restarts); `Ledger.claimResume` hands each resume out once. Aoba (`src/telegram.ts`) runs in the coordinator (`serve`) only when `telegram-token` (private file) and `config.telegram.chatId` both exist; it long-polls with outbound HTTPS only, answers the one owner chat and ignores others, sends Misato's replies, approval cards (each once) and due reminders (checkpoint per message; `stop` waits for a delivery in progress), and applies taps through `Store.decide` with source `telegram`. Requests carry the token in the URL, so errors never echo it and the API base is Telegram's or loopback (tests). Melchior and Balthasar stay deterministic; only Casper's verdict may come from a model and its absence escalates to the owner, never to a grant. Extra seats are veto-only. Grants are single-use, short-lived and bound to the canonical argument hash. Decisions apply once; expiry and the Spear never approve. Events are append-only (enforced by triggers): record corrections as new events. Executed effects are reported by the Spear, never assumed undone. Over the API, approval cards and sortie events are readable by read-only clients and the socket; deciding is REST-only for the admin token (`approvals.decide` is not on the interface edge). Grant IDs never leave the coordinator: not in replies, and not in events (event schema 2; version 1 rows are redacted on read). Card arguments are capped at 8 KB and pages at 5 cards so a page fits one IPC frame. `src/events.ts` is the one event schema (kinds, payload types, `EVENT_SCHEMA_VERSION`) for the ledger, the read APIs and the dashboard: a new kind or a payload change goes there first, and a change a reader could misread bumps the version, which each stored event keeps in its `v` column. Payloads are capped at 16 KB, model verdict reasons at 500 characters and the Spear's listed effects at 50 (with an exact count); event pages stop at 32 KB of payload so they fit one IPC frame, so readers page on with the last sequence rather than assume 50 per page.

## Frontend

Read the style guide. Angular renders registered components, never model-generated JavaScript. The admin token is in a mode-0600 file under NERV_HOME and never reaches the browser by itself. `open` signs a page in: the CLI gets a single-use code (60 s, at most 5 unused) from the running service, the page takes `#code=` from the address, removes it from the address and history, and swaps it once for a **dashboard session** (F-039, owner decision 2026-11-04): random, held only in the service's memory, 12 hours at most, ended by a restart or `sessions revoke`, and allowed everything the admin is except minting codes, revoking sessions or stopping the service (`POST /api/stop`, F-037), so it can never renew itself. The dashboard keeps that session in its tab's sessionStorage so a reload stays signed in; the Angular workspace keeps it in component memory. An admin token pasted by hand stays in memory only and is never stored. No token or code appears in a command line or a URL after sign-in, and the native TLS server offers no codes or sessions. English is the default interface language, with Italian switching. The NERV dashboard lives in `web/public/dashboard/` (shipped with the build, served at `/dashboard/`): `dashboard.js` is the simulation and rendering, `live.js` the live adapter, active only when served with a `#code=` (it maps `/api/sorties`, `/api/sorties/ID`, events, approvals and doctor onto the panels and overrides the simulation's actions). It must run under the service CSP: no inline script, no CDN, no remote fonts (a test checks). Live panels without real data say planned, never show simulated numbers. CLI command names and raw diagnostic messages remain English. Planned cards must say planned; no simulated live devices. Current UI uses typed reminder data and a registered Web Component status surface; model-generated selection is not implemented. PWA installation/offline caching and browser acceptance remain F-004.

## Distributed contracts

`src/kaji.ts` is the Kaji line's trust layer (F-036 phase 1a): the Key of Nebuchadnezzar (Ed25519, scrypt + AES-256-GCM file, passphrase never in argv or env), per-base Ed25519 keys created on first use, and Marduk's registry as append-only records signed by the root and verified on every base against the root pinned by fingerprint (no trust on first use); newest enrolment wins, revocation of a key always wins. `src/kaji-link.ts` is the live link (phase 1b): listens on the base's enrolled address only, signs every request and reply with the base key (method, path, time, nonce, body digest; requests cannot pass as replies), refuses unknown or revoked bases, stale times and replayed nonces, merges last-seen (newest wins, peers' views sanitised to enrolled ids and non-future times), and fetches registry records from a peer that is ahead, each verified against this base's own pinned root. It talks to the registry through `RegistryPort` (scheduler RPC in `serve`, direct in tests). Phase 2 adds health to the heartbeat: each base sends its own state (online or degraded, at most three reasons of 200 characters, the same reasons as its `doctor`), in requests and replies; the receiver sanitises it, stamps its own arrival time and keeps it in the coordinator's memory. Health is first-hand only, never relayed for a third base, and counts only while that base is online; a peer on older code sends none and shows online/offline only. `src/contracts.ts` declares version 1 intentions only; it is not an implemented network protocol. Agent role, model endpoint and execution location remain independent. Node trust requires enrolment; discovery grants no permission. A future broker must enforce privacy, fencing, lease expiry, idempotency and exclusive resources before remote operations. A timeout does not prove that an external action failed. Inspect device state before replaying physical actions. Never silently send local-only input to cloud inference.

### Model routes

`src/model.ts` owns route selection and the two adapters; the brain process is the only caller. Privacy is explicit on every ask and defaults to local-only at the API. Route choice never falls back: a failed or missing route is reported, and local-only text never reaches the cloud adapter (`test/model.test.ts` proves both with a fake provider that counts requests). The cloud key lives in a private file read by the brain, never in env, argv, config, logs or doctor. `model.complete` is a coordinator→brain edge only: the socket cannot ask, REST asks need the admin token. Replies are bounded to `MAX_REPLY_BYTES`. Route health (F-030, `src/route-health.ts`) lives in the brain: every call records the route's outcome (only outages count: unreachable, timeout, HTTP 5xx, key refused, rate limited) and the local route gets a TCP check each minute (no request, no model call, so fake test servers and real ones see nothing extra); the cloud route is never probed. A down route is a `degraded` reason, never a reason to switch routes. Model setup (F-038, `src/model-setup.ts`): `models`, `init` and `GET`/`PUT /api/models` (admin or a dashboard session) read Ollama's `/api/tags` and change only the roles' models and the cloud route's state, through `planModels` and `validateModels` before anything is written, then reload the brain in place; a local model Ollama does not list is refused. The cloud key is never accepted by the API or the dashboard and never returned (only whether it is saved): it is typed at the `models key` terminal prompt (owner decision 2026-11-04).

## Headless installation

Serve built Angular assets and the API from one loopback process on 4317. Development uses 4318; both values must agree with README and tests. Service definitions contain no token, use absolute paths and run as the current user. Never install system services or enable linger on the execution host as part of a code change. Test service rendering and real process lifecycle; distinguish those from launchd/systemd acceptance on a user machine. Keep Quit companion separate from Stop NERV Agency in the future native SwiftUI companion. Read docs/INSTALL.md before changing service lifecycle.

## Isolated runtime and protocol

Read docs/decisions/runtime-boundaries.md. A owns database/ticks during serve; B must not receive the root/provider secrets; C owns API/static/network and child lifecycle. Same-user child processes are workload boundaries, not sandboxes. All IPC methods have schemas and directed authorization in src/rpc.ts. Remote workers, browser ticket pairing and mutation RPC are not implemented; do not turn the local read endpoint into an execution tunnel. Bound frames/queues and fail explicitly on oversize replies. Test a blocked/killed B and A shutdown/recovery separately. Shared surface data is validated in shared/surface.ts; web/src/status-card.ts owns executable code and must use textContent for model/server text. No arbitrary HTML, module URLs or event handlers.

## Native companion and credentials

Read native/README.md and the current pairing decision. Never ship root/provider credentials to the companion, its URL, argv, UserDefaults, logs or Brain. Native TLS is opt-in and pinned before a ticket/client token is sent; no blanket trust bypass or global trust-store installation. NativeAuth owns a small separate private verifier database in C; it must not hold reminder transactions. Tickets are two-minute/single-use, client credentials read-only and revocable with 30-day expiry. Swift tests/build run on macOS CI; Linux does not establish native acceptance. Keychain prompts, menu interaction, notifications and service login/logout need explicit evidence. Keep local Forget pairing distinct from server revocation. Build artifacts are ad-hoc signed previews, not notarized installers.

## Native notifications and OS actions

Read the native guide before changing cursor or permission semantics. Enable establishes a current-head baseline; checkpoints contain sequence plus delivery UUID and are private/atomic, never message content or credentials. Validate whole pages before posting; advance after OS acceptance/reconciliation, never on an error. Do not claim exactly-once banners. History restore resets require an explicit visible warning; corrupt local state must not silently replay old reminders. Every notification request is opt-in; tests use fake sinks and do not prompt CI.

Service commands are fixed user launchctl actions with timeouts and a separate Stop confirmation. A paired runtime must match local plist NERV_HOME. SMAppService mainApp owns companion login only; display real requiresApproval/enabled states. Do not register or modify actual OS services/login items in repository tests. CI validates pure command plans, simulated notification outcomes, pinning and compilation; live Mac permission/banner/login acceptance remains separate.

Native background polling uses `/api/status`, never a recurring full doctor/SQLite integrity scan. Keep an authenticated runtime ping distinct from explicit database diagnostics, and test that polling cannot call quick_check indirectly.
