### F-075: rerun the evaluation cases (Neo Tokyo-3, macOS Terminal)

No model is called; stress and browser take a few minutes. In a worktree of current main:

```bash
npm ci

```

Expected: 7/7 pass, `evals/gauntlet/ledger.json` changes, and `pending` exits 0. Commit the ledger in a PR naming F-075, or tell the agent it may run the command.

<a id="f076-options"></a>
### F-076: how merged main is verified

1. **Require `windows` too and turn on `strict`** (each PR must be up to date with main). Catches combinations before merge; each merge in a busy day then needs a rebase and a rerun.
2. **Add a `push: branches: [main]` trigger** to CI. Every merge is tested after the fact at the cost of one run per merge; a failure is visible within the hour, not prevented.
3. **A GitHub merge queue.** Tests the combination before it lands, without manual rebases. Needs a repository setting and a `merge_group` trigger.
4. **Keep things as they are,** with the agent dispatching a full run on main at each reconciliation. Cheapest, but gaps of hours remain.

The audit recommends option 2, or option 3 if parallel agent work continues at this pace. `ci.yml` is a harness file, so the trigger change should go to the template first unless it's for this project only.

<a id="f077-options"></a>

- **(b) A code-scanning workflow (CodeQL).** One more workflow.

F-077-T02 (patch and minor updates) needs no decision.
