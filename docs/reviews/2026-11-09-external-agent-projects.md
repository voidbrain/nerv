# External agent and evaluation projects, 9 November 2026

Baseline: NERV main `5c7997b`, with F-026 runtime candidate PR #240 considered separately. Scope: the nine owner-supplied projects and their fit to current NERV/Gauntlet boundaries. Primary repository documentation was inspected on 2026-11-09. No package was installed, candidate executed, performance measured or security audit performed. This source assessment does not refresh audit coverage.

## Decision and ownership

Retain the projects below as references and optional adapter candidates. The existing TypeScript runtime, SQLite ledger, grant gate and pinned Gauntlet evidence contract remain the accepted architecture. Current deterministic tests and the first bounded Gemma smoke need none of these dependencies. Reconsider a dependency when a concrete missing capability has a bounded experiment, compatibility/licence review and measurable benefit over the existing implementation.

Gauntlet owns reusable evaluation contracts; NERV owns its domain scenarios, permission/execution enforcement and production acceptance. A reusable upstream release never waits on NERV adoption. External graders, traces, model judges and snapshots cannot grant authority or clear uncertain external effects. Proposed integrations below are alternatives, not delivered features or new acceptance blockers.

## What stays and what remains unimplemented

The evaluation decision retains scripted control-flow tests, separately identified real-model judgment, protected graders/heldouts and owner-controlled promotion. The runtime decision retains a single grant authority and deterministic per-job enforcement under F-049. F-027-T01's durable taint is implemented; F-027-T02 enforced egress remains blocked on F-049's isolation boundary. AgentFS is a candidate to assess against that boundary, not evidence that it exists.

F-006 owns NERV combination/host acceptance and F-074 its pinned evidence adoption and bounded single-model smoke. F-065 owns the control-to-test threat map. F-007 owns evaluated skill improvement/rollback; weight training remains a separate future capability. Chonkie and BrowserGym have no accepted implementation requirement from this assessment alone. Do not reopen completed memory work or add one feature per reference.

Revisit this report when one of those owning records selects an integration, a concrete missing capability appears, upstream APIs/licences/platform enforcement materially change, or a bounded comparison demonstrates a benefit. Pin the exact release/source and review its dependencies before implementation. No model qualification, dependency adoption, security certification or automatic permission change follows from this report.
